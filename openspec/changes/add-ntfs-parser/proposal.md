# Proposal

## Why

Adamite's scan pipeline (docs/ARCHITECTURE.md §2) depends on decoding raw NTFS structures from MFT bytes. Nothing exists yet. A pure, I/O-free, panic-free parser crate is the foundation every later layer builds on (io, core, service, CLI, MCP). Building it first, with fuzzing and real-image tests, makes on-disk format bugs show up early and on Linux, before any Windows-only code exists.

## What Changes

- Create the Cargo workspace: edition 2024, toolchain pinned to Rust 1.99 (`rust-toolchain.toml`, `rust-version = "1.99"`), license `MIT OR Apache-2.0`, shared `[workspace.lints]` and `[workspace.dependencies]`, rustfmt config, `.gitattributes` marking fixtures as binary, and a committed `Cargo.lock`.
- Add a root `deno.json` (with `deno.lock`) as the project's only task runner and script host. It defines the `check`, `fixtures` and `fuzz-corpus` tasks.
- Add the `crates/adamite-ntfs` library: `#![no_std]` with an optional `alloc` feature, and `#![forbid(unsafe_code)]`. Its only runtime dependency is `snafu`, configured for no_std (`default-features = false`, `rust_1_81`). It does no logging; `tracing` starts in `adamite-core`. It provides:
  - Boot-sector geometry decoding, including the signed `clusters_per_record` encoding and the `sectors_per_cluster > 0x80` exponent encoding (clusters up to 2 MiB).
  - FILE record header decoding, NTFS 3.0 and 3.1 header layouts, and in-place update-sequence fixup on caller-owned `&mut [u8]` (512-byte stride).
  - A fused attribute iterator over resident and non-resident attribute headers. Unknown attribute types are surfaced, not rejected.
  - Typed decoders for `$STANDARD_INFORMATION` (48- and 72-byte layouts), `$FILE_NAME`, `$DATA`, `$INDEX_ALLOCATION` (stream descriptor only), `$REPARSE_POINT` (tag plus opaque payload), `$BITMAP` (bit view), and minimal `$ATTRIBUTE_LIST` entries (needed to bootstrap a fragmented `$MFT`).
  - A runlist (mapping pairs) iterator with sparse runs, signed deltas and checked arithmetic.
  - `FileRef` (48-bit record number + 16-bit sequence) and well-known record constants.
  - Small `Copy` snafu-derived error enums that core can map 1:1 onto `ScanStats` counters.
- Add a cargo-fuzz package (`crates/adamite-ntfs/fuzz`, excluded from the workspace, nightly) with targets for boot sector, FILE record, attributes, runlist and typed values.
- Add committed, zstd-compressed NTFS fixture images (≤ 1 MiB total) with JSON manifests. They are generated by `deno task fixtures` (Deno TypeScript scripts driving `mkntfs` and an `ntfs-3g` mount; sudo, regeneration only). Integration tests read them with no system tools.
- Add GitHub Actions CI: an ubuntu and windows matrix running fmt, clippy, test and doc, plus separate `no_std`, `cargo-deny`, Deno (fmt/lint/check) and nightly fuzz smoke jobs.
- Correct docs/ARCHITECTURE.md: `compression_unit` is a `u8` at 0x22; `sectors_per_cluster` uses an exponent encoding; `record_no@0x2C` exists only in NTFS 3.1; `Patch` must carry a `FileRef`, not a `u32` base; non-resident size fields (including `allocated_size`) are valid only when `lowest_vcn == 0`; `$ATTRIBUTE_LIST` is decoded minimally for `$MFT` bootstrap.

## Capabilities

### New Capabilities
- `ntfs/volume-geometry`: Decodes and validates the NTFS boot sector into volume geometry: sector, cluster, file-record and index-record sizes, MFT and MFTMirr LCNs, total sectors and serial.
- `ntfs/file-record`: Decodes FILE record headers, applies update-sequence fixup, classifies records (unused, `BAAD`, not in use, extension, base, corrupt), iterates attributes safely, and defines `FileRef`.
- `ntfs/attribute-decoding`: Typed decoding of the attribute values the scanner consumes: `$STANDARD_INFORMATION`, `$FILE_NAME`, `$DATA`, `$INDEX_ALLOCATION`, `$REPARSE_POINT`, `$BITMAP` and `$ATTRIBUTE_LIST` entries.
- `ntfs/runlist`: Decodes non-resident mapping pairs into virtual-to-logical cluster runs, including sparse runs and per-segment delta reset.

## Impact

- **New code:** workspace root files (`Cargo.toml`, `rust-toolchain.toml`, `deno.json`, `deno.lock`), `crates/adamite-ntfs/**`, `crates/adamite-ntfs/fuzz/**`, `scripts/**/*.ts`, `tests/fixtures/ntfs/**`, `.github/workflows/**`, `LICENSE-MIT`, `LICENSE-APACHE`, `deny.toml`.
- **Docs:** docs/ARCHITECTURE.md is corrected as listed above and gains a Conventions section (snafu, tracing, Deno, toolchain pin).
- **Dependencies:**
  - Runtime: `snafu` only (no_std).
  - Dev: `proptest`, `ruzstd` (pure-Rust zstd decoding for fixtures), `serde`, `serde_json`.
  - Fuzz: `libfuzzer-sys`.
  - Scripts: `jsr:@std/*` modules, pinned in `deno.lock`.
- **Developer environment:**
  - Rust 1.99 (installed automatically by rustup from `rust-toolchain.toml`) and Deno are required.
  - Regenerating fixtures additionally requires `sudo apt install ntfs-3g zstd attr`; normal build and test do not.
  - Fuzzing requires nightly and `cargo install cargo-fuzz`.
- **Downstream:** `adamite-core` will consume this API. Size and alloc accounting policy (WizTree semantics), name selection and UTF-16→UTF-8 policy stay in core.
